# 相机陷阱连拍重复帧核查台

面向野生动物视觉工程师的网页工具：相机陷阱一次连拍的多张图片可能重复进入训练集。
本工具对**当前会话**的至多 6 张同尺寸（≤512×512）帧，利用已有检测框分别比较
**背景区域**与**动物区域**，在容忍轻微 JPEG 重编码差异的前提下给出逐帧建议：

- **保留（keep）**：动物位置或姿态有可辨变化，或无重复关系的独立帧；
- **建议省略（omit）**：背景与动物两类区域都有充分可辨证据、且重复组内
  每两帧均相符时，仅保留最早帧，其余帧建议省略；
- **待核（review）**：任一区域证据不足、指标落在灰区、或重复关系相互矛盾时，
  不自动省略，交人工核查。

分析全程**只读**：原图片、检测框、轨迹与计数不会被修改，会话也不提供任何写入接口。


## 使用流程

1. **数据**：选择 1~6 张尺寸相同、边长均不超过 512 的连拍帧 + 1 个检测 JSON，
   或点击“加载连拍示例”。
2. **分析**：点击“开始重复帧分析”，后台逐帧对比较短时间即可完成。
3. **逐帧核查**：←/→ 键或按钮切换帧，画面叠加检测框；下方列出每帧的
   保留 / 省略 / 待核决定与原因，点击决定行可跳到对应帧。
4. **配对明细**：展开任意两帧的背景、动物区域指标（RMSE、相关系数、
   HOG 姿态距离、细节能量、有效像素数）与判定理由。

切换会话会**立即撤下旧建议**；分析任务携带启动时的会话 id 与输入版本号，
迟到结果若不属于当前会话或版本不一致，前端直接丢弃，不会覆盖新会话。

## 检测 JSON 格式

```json
{
  "detections": [
    {"id": "box0", "frame": 0, "rect": [x, y, w, h]}
  ]
}
```

- `id`：框号（字符串或数字，全局唯一）
- `frame`：帧号，0 起，须小于上传图片数
- `rect`：`[x, y, 宽, 高]`，宽高为正；允许略微越界，裁剪到画面后须仍有正面积

会话内可下载当前检测 JSON：`GET /api/sessions/{sid}/detections.json`。

## 比对方法

两类区域独立比较，图像先做轻度高斯模糊以抑制 JPEG 块效应与传感器噪声：

| 区域 | 像素范围 | 指标 |
| --- | --- | --- |
| 背景 | 两帧所有检测框**并集之外** | RMSE、相关系数、细节能量 |
| 动物 | 两帧检测框的**交集** | RMSE、相关系数、HOG-lite 姿态距离、细节能量 |

判定逻辑（保守，自动省略门槛最高）：

1. 两帧检测框**无交集** → 动物整体移位，位置变化的强证据，判 **different**；
2. 动物区域 RMSE 强超阈，或 HOG 姿态距离超阈且 RMSE 同步升高、相关性仍强
   → 位置/姿态有可辨变化，判 **different**（保留该帧）；
3. 背景与动物都证据充分，且 RMSE / 相关 / HOG 全部落入相符区间
   → 判 **duplicate**；
4. 有效像素太少、细节能量过低（平坦或严重压缩/模糊）、相关性被伪影拉低，
   或指标处于灰区 → 判 **unknown**（待核），不自动省略。

组级建议由并查集按 duplicate 边分组：

- 纯重复组件且组内每两帧均显式 duplicate → 保留最早帧、省略其余；
- 组件内部出现 diff（重复关系相互矛盾）或 unknown（证据不足）→ 整组待核；
- 重复组与组外帧存在证据不足配对 → 整组待核；
- 孤立单帧默认保留。

阈值在 `app/compare.py` 顶部集中定义，并由测试按三类场景锁定：
高质量重编码（q≥50）重复帧、姿态/位置变化帧、严重压缩的歧义帧。

## 内置连拍示例

6 帧 384×288 画面：

- 帧 0/1/2：同位置同姿态，仅传感器噪声与 JPEG 差异 → 重复，保留帧 0、省略帧 1/2；
- 帧 3：动物移动到画面另一侧且姿态变为低头，检测框与其他帧不相交 → 保留；
- 帧 4：动物移动到画面中部、侧身转向 → 保留；
- 帧 5：与帧 4 同位置同姿态，但强模糊 + 强噪声 + q18 重编码，
  相关性被压缩伪影拉低 → 与帧 4 一起标为待核，不自动省略。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sessions` | 上传图片（`images`，1~6 张）+ 检测 JSON（`detections`），创建会话 |
| POST | `/api/example` | 创建内置连拍示例会话 |
| GET | `/api/sessions/{sid}` | 会话数据（含输入版本号） |
| GET | `/api/sessions/{sid}/frames/{i}` | 第 i 帧原始图像 |
| GET | `/api/sessions/{sid}/detections.json` | 下载检测 JSON（原样返回） |
| POST | `/api/sessions/{sid}/analyze` | 启动异步重复帧分析，返回任务 id 与输入版本 |
| GET | `/api/jobs/{job_id}` | 查询任务状态与结果（携带会话 id 与版本号） |

## 说明与限制

- 会话与任务保存在进程内存中，重启即清空（单用户工具定位）。
- 上限：6 帧、图像边长 512、30 个检测框、单图 20 MB。
- 分析为只读操作：没有任何修改图片、检测框、轨迹或计数的接口，
  会话创建后版本号保持不变；任务的会话/版本校验只用于丢弃迟到结果。
- 比对基于灰度结构指标，不使用外观嵌入向量；阈值面向相机陷阱固定机位、
  同尺寸连拍校准，机位明显移动或画面整体光照剧变时会倾向保守的“待核”。
